BIOBUZZ — מהדוגמה המוכנה לבנייה עצמאית

שלב א: מכירים ומריצים
1. פותחים את פרויקט הפתרון לפי START-HERE-HE.txt ובונים אותו.
2. בוחרים שיעור אחד, מתאימים את החומרה ומריצים את ה־OpMode המתאים.
3. מסבירים בקול את הזרימה: שלט → OpMode → Command → Subsystem → חומרה.
4. משנים ערך קטן ומוסבר, בונים שוב ומשווים telemetry לפני ואחרי.

שלב ב: בונים בעצמכם
1. משאירים את הפרויקט המוכן כעותק עיון. מחלצים את ה־ZIP שוב לתיקיית עבודה נפרדת.
2. מתחילים מהתשתית הקיימת. משכתבים את מחלקות השיעור באותו עותק עבודה,
   בהדרגה ובאותם שמות וקבצים, כדי שלא ייווצרו מחלקות או OpModes כפולים.
3. עובדים לפי LESSON-MAP.csv: תחילה Subsystem, אחריו Command ולבסוף TeleOp.
4. כותבים לפני המימוש: מה הקלט? מה הפלט? מי בעל החומרה? מתי מפסיקים?
5. אחרי כל חלק קטן בונים; לאחר שלב שלם מריצים ומסבירים את התוצאה.
6. משווים לפתרון רק לאחר ניסיון עצמאי. מתעדים מה שונה ולמה.

סדר מוצע
מנוע יחיד → מאקאנום → חיישנים → סרבו → מעלית → קבוצות פקודות → אוטונומי וראייה.
מבנה הפרויקט, Git ובדיקות מלווים את כל השלבים.

בדיקת הבנה
לכל שיעור: הדגמת פעולה, הסבר תפקיד כל מחלקה, התאמת שמות חומרה,
טיפול בשחרור כפתור וב־STOP, ושלוש תקלות לדוגמה והדרך לאתר אותן.
ללוגיקה שאינה תלויה בחומרה מוסיפים בדיקת תנאי קצה ל־TeamCode/src/test.

משימת גמר קבוצתית
מתכננים ובונים רובוט למשימת הפרחים בדקה האחרונה כפי שהוגדרה לקבוצה.
מתחילים ממפרט מכני, פעולות נהג, מבנה מערכות ומדדי הצלחה לפי החוקים שקיבלתם.
FlowerScoring הוא כלי עזר לימודי; הפרויקט המוכן אינו פתרון מלא לתחרות.
